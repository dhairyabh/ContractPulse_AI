# ContractPulse AI: ML Risk Foundation

This folder adds the first reproducible ML foundation without changing the existing frontend or either Spring Boot backend.

## Current status and limitations

- The included dataset is **synthetic development data**, generated by `generate_dataset.py` with seed 42.
- Synthetic targets are simulated and are not labels verified against actual project outcomes.
- Evaluation metrics are useful for checking that the training/evaluation pipeline works; they are **not evidence of real-world accuracy**.
- This stage predicts two binary targets: `delay_risk` and `cost_overrun_risk`. Milestone-specific prediction will be added only after suitable milestone-level labelled data is available.
- No Spring Boot, PostgreSQL, frontend, or live API integration is changed in this stage.

## Setup (Windows PowerShell)

```powershell
cd ml-risk
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python generate_dataset.py --rows 2500 --seed 42
python train_models.py
python -m pytest -q
```

If PowerShell blocks activation, run the commands using `ml-risk\.venv\Scripts\python.exe` directly.

## Dataset fields

Raw columns include project budget, planned duration/progress, actual progress, payment percentage, milestone delay days, change-order count, inspection counts/failures, contractor delay history, and planned/actual cost-to-date. All generated rows have `data_origin=synthetic`.

Engineered features include:

- `progress_variance`
- `schedule_variance`
- `payment_progress_ratio`
- `milestone_delay_days`
- `change_order_frequency`
- `inspection_failure_rate`
- `contractor_delay_history`
- `cost_variance_pct`
- `planned_duration_days`
- `budget_crores`

The two target columns are `delay_risk` and `cost_overrun_risk` (0/1).

## Model comparison

The training script compares Logistic Regression, Random Forest, and XGBoost for both targets. It uses a stratified 80/20 train/test split with a fixed random seed and reports accuracy, precision, recall, F1, ROC-AUC, and Brier score. The selected model is chosen by F1 then ROC-AUC on the held-out synthetic test set; this is a prototype selection rule, not final production validation.

Artifacts are written to `models/` and `reports/model_comparison.json`. The `predict.py` helper expects engineered features and returns a probability percentage plus an explicit synthetic-data warning. Do not expose it to production users as a validated risk estimate.

## Before real-world use

1. Source a suitable public or permissioned construction/project execution dataset with outcome labels.
2. Document provenance, licences, missingness, and whether records are real or synthetic.
3. Define outcome windows and labels before training; ensure no feature contains information only known after the prediction date.
4. Split by project/time where appropriate to avoid leakage between snapshots from the same project.
5. Evaluate calibration and operational precision/recall on an untouched real-world test set.
6. Only then integrate model probabilities into Spring Boot and persist versioned prediction records.
